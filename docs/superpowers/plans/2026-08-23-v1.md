# movieranker.win v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build v1 of movieranker.win per the spec: TMDB-powered list building → shared-screen head-to-head ranking → account-gated save → polished public list pages.

**Architecture:** Single Next.js App Router app on Vercel. Pure ranking engine in `src/lib/ranking.ts` (fully unit-tested, no I/O). TMDB access only through `src/lib/tmdb.ts` (server-side, Next.js `revalidate` caching). Anonymous sessions live in localStorage; saving persists to Supabase Postgres with owner-only RLS. Public read of finished lists, no auth required.

**Tech Stack:** Next.js 15 (App Router, TS strict), Tailwind CSS v4, Supabase (Postgres + Auth: email/password, magic link, Google & Microsoft OAuth), `nanoid`, Vitest.

**Spec:** `docs/superpowers/specs/2026-08-23-movieranker-design.md`

## Global Constraints

- Node ≥ 20, npm only (no pnpm/yarn).
- TypeScript `strict: true`.
- ALL TMDB requests server-side (`src/lib/tmdb.ts` only). Client never sees `TMDB_API_KEY`. Poster image URLs are client-safe: `https://image.tmdb.org/t/p/w500{poster_path}`.
- Posters ALWAYS render in true ratio: container `aspect-[2/3]`, img `object-cover`. Never squares/crops.
- Motion: 150–250 ms ease-out micro-transitions only; every animation wrapped so `prefers-reduced-motion` disables it.
- Engine constants (from spec): Elo K=32, base rating 1000, stability N=6 consecutive stable votes, adjacency gap threshold 50 points.
- No `votes` table (spec: deliberate omission).
- Dark-cinema tokens defined once in `globals.css`: `--bg #0d0d10`, `--surface #17171c`, `--accent amber ~#f5a524`, `--accent-red #e5484d`, `--text #ececf1`, `--muted #8b8b94`.
- Touch targets ≥ 44 px. Every interactive element has hover/focus-visible/active/disabled/loading designs.
- Lists table PK is short URL-friendly nanoid (not uuid).

### Task 7: Supabase — schema, RLS, auth clients

**Files:**
- Create: `supabase/schema.sql` (run manually in Supabase dashboard), `src/lib/supabase/server.ts`, `src/lib/supabase/client.ts`

**Schema** (verbatim from spec):

```sql
create table lists (
  id text primary key,
  owner_id uuid not null references auth.users(id),
  title text not null,
  participants text[] not null default '{}',
  status text not null default 'draft',
  created_at timestamptz not null default now()
);
create table list_movies (
  id bigint generated always as identity primary key,
  list_id text not null references lists(id) on delete cascade,
  tmdb_id int not null, title text not null, poster_path text, release_year int,
  elo real not null default 1000, comparisons int not null default 0,
  parked boolean not null default false, final_rank int
);
alter table lists enable row level security;
create policy "owner all" on lists for all using (auth.uid() = owner_id);
alter table list_movies enable row level security;
create policy "owner via list" on list_movies for all using (
  exists (select 1 from lists l where l.id = list_id and l.owner_id = auth.uid())
);
create policy "anyone reads done lists" on lists for select using (status = 'done');
create policy "anyone reads done movies" on list_movies for select using (
  exists (select 1 from lists l where l.id = list_id and l.status = 'done')
);
```

Clients: standard `@supabase/ssr` browser + server factories (cookie-based session).

```
POST /api/lists            body: { title, participants, status: 'draft'|'done', movies: RankedMovie[] (+finalRank when done) }
                           → 201 { id } ; 401 if no session
PATCH /api/lists/[id]      body: partial { title?, participants?, status?, movies?: ({tmdbId} & Partial<RankedMovie> & {finalRank?})[] } → 204 ; 401/403 non-owner

```

POST generates `id = nanoid(10)`. PATCH upserts/deletes movie rows by tmdbId diff. Both handlers use server Supabase client; RLS is the enforcement, handlers return 403 on RLS failure.
